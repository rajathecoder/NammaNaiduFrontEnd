## 2024-05-24 - Parallelizing API Requests in Matches
**Learning:** In the `Matches` component, three independent API endpoints (opposite gender profiles, shortlisted actions, and interest actions) were being fetched sequentially, creating an unnecessary network waterfall that significantly degraded load performance. Additionally, the filtered profiles list was being re-calculated synchronously without memoization.
**Action:** Always verify if sequential `await` calls in React data-fetching components are truly dependent on each other. If not, bundle them into a single concurrent `Promise.all` array (ensuring individual `.catch()` fault tolerance) to parallelize network I/O. Use `useMemo` for derived list calculations to prevent recalculation overhead during component re-renders.
