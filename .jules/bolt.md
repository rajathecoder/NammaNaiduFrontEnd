## 2024-06-19 - Parallelizing interdependent-looking actions and array filtering memoization
**Learning:** React components (like the Matches page) often fetch their main payload, and then conditionally fetch auxiliary user data (like user-specific shortlists and interests) only after the primary request resolves. Even if these endpoints feel semantically dependent on the user's primary profile load, they only truly require the `authData.token` to execute safely and successfully, which means they can be aggressively parallelized with `Promise.all` alongside the primary request to massively speed up rendering and load times. Furthermore, expensive array operations (like filtering matches based on dates or user actions) that are invoked inline during the render cycle are easily identified bottlenecks. Using `useMemo` strictly ties their re-calculation to state boundaries rather than every minor DOM update or render cycle.
**Action:** When inspecting sequential `await fetch` calls, always verify if subsequent calls actually require the `data` of the preceding calls. If they only require the same `authData.token`, lift them into a `Promise.all` block. Additionally, when encountering `.filter` or `.map` over large arrays in a React component's body, explicitly extract and wrap them in `useMemo`.
