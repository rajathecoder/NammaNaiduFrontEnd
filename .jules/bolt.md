## 2024-05-15 - [Backend API Efficiency: N+1 queries]
**Learning:** We are doing N+1 API queries on the frontend to fetch opposite gender profile photos (`GET /api/users/photos/:id`) after fetching the opposite gender profiles in `fetchOppositeGenderProfiles`. However, looking at `Matches.tsx` and the fact that `personPhoto.photo1` is directly accessible, it seems the backend API (`/api/users/opposite-gender-profiles`) already includes the `personPhoto` data directly in the nested payload for each profile. This means the separate N+1 calls in `HomePage.tsx` and `useHomePageData.ts` to fetch photos individually are completely unnecessary and slow down the initial load.
**Action:** When working on lists that render profiles, always check if the nested `personPhoto` object is already provided in the primary API response before making additional N+1 photo fetch calls.
