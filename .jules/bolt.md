## 2024-03-27 - Frontend UI Test Verification with Context Auth
**Learning:** Frontend UI components like `UserProtectedRoute` rely heavily on the specific shape and keys of mocked authentication data (e.g. `token`, `userId`, `accountId` specifically rather than just an `authData` object). When using Playwright for verification, failing to exactly replicate `localStorage` as expected by `utils/auth.ts` will silently redirect components back to the Login page, preventing any target verification from occurring and resulting in generic selector timeout errors.
**Action:** When writing Playwright scripts to verify authenticated routes, strictly check the authentication utilities (e.g. `src/utils/auth.ts`) to understand exactly which keys are used for validation and manually mock all required individual keys in `localStorage`, rather than assuming a single JSON object will suffice.
