## 2023-10-27 - [High] CMS Content XSS Fallback Sandbox
**Vulnerability:** XSS payload injections through `dangerouslySetInnerHTML` in multiple CMS pages (ContentPage, ContactUs, CMSPage admin preview).
**Learning:** External authorization boundaries (like adding standard packages such as `dompurify`) create significant tension when patching XSS. The custom `DOMParser` fallback sanitizer approach works securely in modern React SPA contexts because `DOMParser` inherently handles complex entity decoding that defeats Regex-based sanitizers. However, XSS bypasses via URI control characters (like `java\0script:`) and null byte replacements (`\ufffd`) must be explicitly handled, as `DOMParser` converts `\x00` to `\ufffd` automatically in attributes.
**Prevention:** If an external library boundary is enforced, always use an actual HTML parser (like `DOMParser`) for sanitization rather than raw Regex replacement. Explicitly remove inline event handlers (`on*`), `<script>` tags, and actively filter control characters and the unicode replacement character `\ufffd` in `href` and `src` attributes.
