## 2024-04-13 - [CRITICAL] XSS via dangerouslySetInnerHTML in CMS Pages
**Vulnerability:** Found multiple instances where dynamic content (from API or user input) was injected directly into the DOM using React's `dangerouslySetInnerHTML` prop without any prior sanitization (e.g., `src/pages/CMS/ContentPage.tsx`, `src/pages/CMS/ContactUs.tsx`, `src/admin/pages/CMS/CMSPage.tsx`). This exposes the application to severe Cross-Site Scripting (XSS) attacks.
**Learning:** React escapes content by default when using JSX bindings (`{content}`), but `dangerouslySetInnerHTML` explicitly bypasses this protection. If the source of the HTML is not 100% trusted (like CMS content that might be edited by multiple users or compromised), it must be sanitized.
**Prevention:** Implemented a new `SanitizedHTML` reusable component that wraps DOMPurify (`DOMPurify.sanitize(html)`). Going forward, never use `dangerouslySetInnerHTML` directly with raw variables. Instead, always use the `<SanitizedHTML html={content} />` wrapper to ensure all HTML is securely stripped of malicious scripts before rendering.
