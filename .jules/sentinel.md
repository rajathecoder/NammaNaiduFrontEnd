## 2025-02-28 - Centralized Credentials and Silent Fallbacks
**Vulnerability:** Hardcoded API keys and configuration values for critical third-party services (Firebase, Razorpay) were embedded directly in source code as fallback values. These fallback values would be used silently if environment variables were missing, masking configuration errors and exposing test credentials in client bundles.
**Learning:** The presence of `|| 'hardcoded_value'` patterns for environment variables creates a false sense of security. Even if `.env` is ignored, developers often commit fallback strings during initial setup or testing, permanently writing them into Git history and making them accessible to anyone who analyzes the bundled source.
**Prevention:** Strictly forbid hardcoded fallbacks for sensitive keys. Enforce 100% reliance on environment variables (e.g., `import.meta.env.KEY`) combined with explicit runtime validation checks (e.g., throwing errors or failing safely) to guarantee that missing configurations result in immediate, noisy failures rather than silent vulnerability exposure.
