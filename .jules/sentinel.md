## 2026-08-26 - [Custom DOMParser Sanitizer Bypasses]
**Vulnerability:** A custom HTML sanitizer using DOMParser and rudimentary regex to strip control characters and block malicious URI schemes is highly insecure and trivial to bypass.
**Learning:** Checking for malicious URIs using `.startsWith('javascript:')` is insufficient because browsers ignore leading whitespace in URIs. An attacker can use `href=" javascript:alert(1)"` (with a leading space, `\x20`) which bypasses a regex that only strips control characters (`\x00-\x1f`). Additionally, checking only `href` and `src` attributes leaves vectors like `action` (on `<form>`), `data` (on `<object>`), or `srcdoc` (on `<iframe>`) open. Although adding new security dependencies requires asking first, rolling a custom HTML sanitizer results in "security theater" and is a blocking anti-pattern.
**Prevention:** Never attempt to roll a custom HTML sanitizer. Always prioritize asking for permission to install an established, battle-tested library like `dompurify` or `isomorphic-dompurify`.
