## 2026-06-26 - [HIGH] Fix XSS vulnerability in CMS pages
**Vulnerability:** The application was passing unvalidated raw HTML strings fetched from the backend API directly into React's `dangerouslySetInnerHTML` prop across multiple CMS-related components (`ContentPage.tsx`, `ContactUs.tsx`, `CMSPage.tsx`).
**Learning:** This architectural pattern is common when building dynamic CMS systems, but developers often assume the backend data is inherently "safe". Without frontend sanitization as a defense-in-depth measure, any compromised backend record (e.g., via an insecure admin panel or database injection) could execute arbitrary Javascript in the context of the user's browser (Stored XSS).
**Prevention:** Always implement a robust frontend sanitization layer (e.g., `DOMPurify.sanitize()`) wrapped in a utility function (`sanitizeHTML`) before passing any dynamic string to `dangerouslySetInnerHTML`, regardless of the data's origin. Ensure the utility is SSR-safe by verifying the window object exists.
