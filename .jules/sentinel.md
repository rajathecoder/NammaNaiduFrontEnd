## 2024-05-20 - [Fix XSS Vulnerabilities in CMS Rendering]
**Vulnerability:** The application was passing unsanitized HTML directly into React's `dangerouslySetInnerHTML` in multiple CMS components (`ContentPage`, `ContactUs`, `CMSPage`). A malicious user with CMS write access could inject malicious scripts or event handlers (XSS).
**Learning:** While the project has a strict instruction against adding unapproved third-party dependencies and recommended writing a custom `DOMParser`-based sanitizer, doing so introduces severe security flaws (missing `javascript:` URIs, unquoted event handlers, etc.). Security requirements supersede generic memory constraints; establishing a strong defense against XSS necessitates using a battle-tested library like `dompurify` rather than custom regex/DOM parsing.
**Prevention:** Always use established security libraries (like `dompurify`) to sanitize HTML strings before passing them to `dangerouslySetInnerHTML`. Do not attempt to write custom HTML sanitizers, as they are inherently prone to bypasses.
